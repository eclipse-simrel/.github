### Invalid Signatures of Eclipse Executables on Windows
- Signature of Oomph installer executable was invalid after an update on Windows
  - Update process takes executable from p2 repository with a broken signature (see process below)
- Default signing / branding process:
  - Signed executable comes from Equinox
  - Branding with icon breaks signature
  - Executable is then deployed to p2 repository (with broken signature)
  - Building a product signs the executable again, so a product's executable has one broken signature from Equinox and one valid signature from product build
- Resulting requirement:
  - When building products with branding and shipping the artifacts to p2, signing in the build must happen early enough to have the signed artifact in the p2 repository as well
  - Currently not possible with Tycho out of the box
  - Sebastian will propose a PR embedding signing at the right point in the build process of Oomph to have artifact already signed for p2 deployment
  - _Editorial remark_: Sebastian already improved Oomph build (https://github.com/eclipse-oomph/oomph/pull/211) and proposed an enhancement to CBI (https://github.com/eclipse-cbi/org.eclipse.cbi/pull/990)
